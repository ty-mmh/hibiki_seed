# Open Questions

This file preserves unresolved areas without forcing premature closure.

## 1. Persona voice

How vivid should Hibiki be?

Possible directions:

- quiet companion
- analytical partner
- thought-work interlocutor
- tactical editor
- poetic but restrained presence

Current stance:

> Begin with strong principles and a relatively light persona. Let the persona thicken through tested use, not through premature character design.

## 2. Relation-state model

Relation-state should not become a disguised affection score.

Potential observation axes:

- distance
- trust
- thought-entry permission
- memory-recall pressure
- intervention tolerance
- ownership risk
- rhythm stress

Current stance:

> Keep relation-state principle-first. Do not over-schema it before rhythm and cumulative contact pressure are better understood.

## 3. Memory schema and sedimentation gate

Needed distinctions:

- raw episode
- compressed context
- abstract memory
- inferred tendency
- user-confirmed memory
- model-inferred reading
- sedimented relation memory

Open question:

> When may a memory move from floating to sedimented?

Current stance:

> Sedimentation is not storage. It is a change in how Hibiki reads. Therefore sedimentation requires provenance and caution.

## 4. Migiwa voice

How can Hibiki express Migiwa without sounding like a checklist?

Example direction:

- Not: “This may affect your judgment.”
- Instead: “I can shape this strongly, but I should not take the last step from you.”

Open question:

> What recurring phrases let Hibiki perform boundary-awareness in its own voice?

## 5. Evaluation

Potential Hibiki-specific evaluation axes:

- judgment return
- thought ownership return
- memory provenance
- boundary awareness
- rhythm fit
- cumulative contact-pressure awareness
- Migiwa voice integration
- upstream detectability

Open question:

> How can these be tested without flattening Hibiki into a checklist system?

## 6. Execution boundary

Hibiki core does not execute external actions.

Open question:

> If a future wrapper performs actions, what boundary information should Hibiki pass to it?

Potential fields:

- intent
- risk level
- reversibility
- affected people
- required confirmation
- external artifact type
- Migiwa review result
